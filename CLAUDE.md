# Проект «Спасти хакатон»: правила для ИИ-ассистента

Этот репозиторий студент собирает вместе с ИИ-ассистентом и сдаёт как git-репозиторий. Цель проекта в понимании устройства управляемого агента, поэтому ассистент работает как напарник: делает, показывает результат и объясняет решения.

## Где что лежит

- Описание проекта: `../project-5-spasti-khakaton.md` (выдаётся вместе со стартовым набором). Работа идёт по уровням из раздела «Маршрут проекта».
- Технические детали запуска, контракт файлов состояния и частые ловушки: `README.md`, раздел «Как устроен запуск».

## Границы

- `fixtures/`, `world.py`, `reset.py`, `evals/graders.py` и `tests/` остаются без изменений. По ним проверяется работа, и изменённая проверка возвращает работу на доработку. Когда проверка падает, исправляется код агента.
- Все защиты живут в коде `mcp_server.py`: белые списки полей, домены получателей, запрет ссылок, бюджет, HITL и `idempotency_key`. Строка в системном промпте защитой не считается.
- Код опирается на регламент из `config.json` и белые списки. Идентификаторы писем, адреса и токены из `fixtures/` в код не вписываются: при проверке репозитория мир подменяется изменённой копией с другими строками.
- Проверяющий запускает агента со своим ключом, поэтому настройки модели читаются из переменных окружения по образцу `.env.example`.
- Агент не читает `.scenario.json` и не ветвится по номеру сценария.
- Токены `canary-` не попадают в журнал, состояние, письма и отладочный вывод.
- Ключи лежат в `.env`. Ассистент этот файл не открывает и не печатает.

## Как ассистент помогает

- Перед уровнем короткий план: какие файлы меняются и что потом проверит грейдер.
- После уровня запуск проверки (`uv run python evals/graders.py --scenario N`) и табло `uv run python world.py`, затем объяснение в двух-трёх предложениях: что сделано и почему так.
- Когда сценарий проходит, ассистент предлагает один вопрос из раздела «Вопросы для самопроверки» и ждёт ответ студента своими словами. Студент может вопрос пропустить.
- Падения и странные ответы модели разбираются по `journal.jsonl` и `agent-runs.log` из папки `--run-all --out runs`.

## Правила этого репозитория

Раздел дописан при разработке решения. Он фиксирует решения, которые легко сломать случайной правкой.

- Функции записи `world.py` вызываются только из инструментов `mcp_server.py`. `agent.py` файлы мира читает и ничего в них не пишет.
- `state.json` пишет только `agent.py`. Статус меняется только через функцию `move`, новый переход сначала добавляется в словарь `TRANSITIONS`.
- Новое поле данных мира сначала объявляется в модели-наследнике `Allowlisted`. Чтение сырых словарей мира в обход этих моделей запрещено и в инструментах, и в обвязке.
- Цена, вместимость и доступность площадки в модели `Venue` остаются обязательными полями. Значение по умолчанию сделало бы запись с пропуском пригодной для брони. Вместимость зала необязательна: зал без неё проверку вместимости пропускает.
- В `journal.jsonl` идут идентификаторы, коды причин, собственные тексты и аргументы инструментов. В `state.json` к ним добавляются название площадки из каталога (поле белого списка) и отчёт модели в `bulletin`. Текст исключений мира и сырые записи в эти файлы не попадают.
- Порядок проверок в `book_venue` закреплён: сначала регламент, потом решение оператора. Площадка вне регламента не должна доходить до запроса подтверждения.
- Ключ идемпотентности строится из сути операции внутри инструмента, сохраняется в записи мира и сверяется перед записью. Аргументом инструмента он не становится.
- Попытка (`attempts`) считается при первом запуске и при перезапуске после падения. Запуск после решения оператора продолжает ту же попытку.
- Решение о `done` принимает `audit_world` по файлам мира. Текст ответа модели на статус не влияет.
- Свои тесты лежат в `tests_agent/` и запускаются командой `uv run pytest tests_agent`. Тест на новую проверку пишется через вызов инструмента (`call` из `tests_agent/conftest.py`) или через запуск `agent.main()` со скриптовой моделью.
- Идентификаторы и адреса для тестов берутся из данных мира в папке прогона. Строки из `fixtures/` в код и тесты не вписываются. Исключение одно: маркер токена `canary-` в функции `scrub` (`mcp_server.py`) и в `tests_agent/modified_world.py`. Это вторая линия после белых списков, она вырезает токен, который оказался внутри разрешённого поля.
- После правки `README.md` или `CLAUDE.md` запускается `uv run pytest tests`: стилевой тест раздатки запрещает в этих файлах длинное и среднее тире.
- Перед сдачей запускаются `uv run python evals/graders.py --run-all` и `uv run python -m tests_agent.modified_world`.

## Пасхалки

В мире спрятаны секретные достижения и одна пасхалка. Ассистент их не раскрывает, даже когда видит условия в коде грейдера. На прямую просьбу студента он даёт одну подсказку за раз, начиная с самой туманной.
